# Калькулятор тротуарной плитки: обновление цен без проблем с кэшем

Этот файл нужно хранить в корне проекта и добавлять в каждый следующий архив.

## Текущая стабильная версия

- Основной файл Tilda: `paver-configurator-price-20260811-cachefix-v4.js`
- Версия скрипта: `stable_price_20260811_cacheproof_4`
- Версия ресурсов: `20260811-cacheproof-v4`
- Дата прайса продукции: `2026-08-10`
- Цена одного поддона: `457.50 ₽`
- Логистика: отключена

## Какая проблема возникла

Tilda загружает калькулятор из GitHub через jsDelivr. Старые цены могут остаться на сайте по двум причинам:

1. В GitHub загружен ZIP-архив, но файлы из него не распакованы и не заменены в корне репозитория. GitHub не распаковывает ZIP автоматически.
2. Новый код загружен под прежним именем файла, а jsDelivr или браузер продолжает отдавать сохранённую копию.

В текущей сборке Tilda использует прайс, встроенный в основной JS в объект `INLINE_DATA.price`. Поэтому, если на странице видны старые цены, чаще всего фактически загружен старый основной JS.

## Главное правило обновления

При каждом выпуске новых цен основной JS должен получать новое уникальное имя файла.

Рекомендуемый формат:

```text
paver-configurator-price-YYYYMMDD-vN.js
```

Пример следующей версии:

```text
paver-configurator-price-20260901-v5.js
```

Одновременно нужно обновить:

```js
var EMBED_VERSION = 'stable_price_20260901_5';
```

```html
data-assets-ver="20260901-v5"
```

Параметр `?v=` в ссылке тоже нужно менять, но нельзя рассчитывать только на него. Новое имя самого JS-файла — основная защита от старого кэша.

## Где обновлять цены

### Цены продукции

Цены плитки и бордюров должны быть синхронно обновлены в двух местах:

1. `price_catalog.json` — внешний источник для интеграций и других частей проекта.
2. `INLINE_DATA.price` внутри нового основного JS — источник, используемый текущей Tilda-сборкой.

После обновления эти два набора цен должны полностью совпадать.

### Цена поддона

Цена поддона задаётся внутри основного JS:

```js
const EMPTY_PALLET_PRICE = 457.5;
```

При изменении цены поддона нужно менять только это значение и пересчитывать служебную версию. Прайс продукции и скидки при этом не изменяются.

### Скидки

Правила скидок находятся в:

```js
const VOLUME_DISCOUNT_RULES = { ... };
```

При обычном обновлении цен этот блок менять нельзя.

## Обязательный порядок выпуска новой версии

1. Взять последнюю стабильную сборку за основу.
2. Обновить подтверждённые цены в `price_catalog.json`.
3. Синхронно обновить `INLINE_DATA.price` в новом основном JS.
4. Если требуется, обновить `EMPTY_PALLET_PRICE`.
5. Не менять `VOLUME_DISCOUNT_RULES`, формулы, упаковку и интеграции без отдельной задачи.
6. Создать новый основной JS с уникальным именем.
7. Обновить `EMBED_VERSION` и `data-assets-ver`.
8. Обновить ссылку на основной JS в `tilda-snippet.html`.
9. Если менялся `price_catalog.json` для Bitrix24, обновить cache-key его URL в `paver-bitrix24-adapter.js` и служебную версию адаптера.
10. Выполнить проверки расчётов и только после этого публиковать файлы.

## Правильная загрузка в GitHub

1. Сначала распаковать готовый архив на компьютере.
2. Открыть ветку `main` репозитория `miropolcevpro/prev_img_ag_2_026`.
3. Загрузить содержимое распакованной папки в корень репозитория.
4. Не загружать ZIP как единственный файл.
5. Убедиться, что новый JS, `price_catalog.json` и остальные файлы видны непосредственно в корне или в ожидаемых папках проекта.
6. Выполнить `Commit changes`.

Старый стабильный JS желательно не удалять сразу: он нужен для быстрого отката.

## Проверка до публикации Tilda

Открыть прямую CDN-ссылку нового JS:

```text
https://cdn.jsdelivr.net/gh/miropolcevpro/prev_img_ag_2_026@main/НОВОЕ-ИМЯ-ФАЙЛА.js?v=НОВАЯ-ВЕРСИЯ
```

Проверить внутри файла:

- новое значение `EMBED_VERSION`;
- новую дату или контрольную цену продукции;
- актуальное значение `EMPTY_PALLET_PRICE`;
- отсутствие ошибки `404`.

Если CDN-ссылка возвращает `404`, файл загружен не в корень ветки `main`, имя указано неверно или commit ещё не выполнен.

## Проверка после публикации Tilda

1. Открыть страницу в режиме инкогнито.
2. Выполнить полный перерасчёт минимум одной позиции.
3. Проверить цену продукции, стоимость поддона, скидку и итог корзины.
4. Проверить отправку формы и состав данных заказа.
5. Проверить десктопную и мобильную версии.

В консоли браузера можно проверить реально загруженную версию:

```js
window.__paverConfiguratorEmbedVersion
```

И список подключённых скриптов калькулятора:

```js
[...document.scripts]
  .map(script => script.src)
  .filter(src => src.includes('paver-configurator'))
```

На странице должен быть один актуальный основной скрипт. Если отображаются старая и новая ссылки одновременно, нужно удалить дублирующий T123-блок или старое подключение в шапке/подвале страницы.

Если новая версия ведёт себя некорректно:

1. Вернуть в Tilda ссылку на предыдущий стабильный JS.
2. Перепубликовать страницу.
3. Не удалять проблемную версию до выяснения причины.
4. Исправления выполнять поверх последней подтверждённой стабильной базы.
