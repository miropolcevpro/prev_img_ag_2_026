# Интеграция калькулятора с CRM-формой Bitrix24

## Идентификация формы

Из кода `data-b24-form="inline/10/6me0os"` следует:

- ID формы: `10`
- код формы: `inline/10/6me0os`
- loader: `https://cdn-ru.bitrix24.ru/b10322535/crm/form/loader_10.js`

Адаптер использует эту же форму. Виджет в правом углу можно оставить. Кнопка калькулятора открывает второй экземпляр той же формы в аккуратном модальном окне, поэтому не зависит от внутренней разметки виджета.

## Обязательная настройка скрытых значений

Текущие статические значения (`0`, `{}`, `Не указано`) нельзя адресно заменить через `form.setProperty()`. В каждом скрытом поле установите уникальный параметр:

| Поле в CRM | Значение скрытого поля |
|---|---|
| Расчёт калькулятора | `%paver_order_text%` |
| Полный состав заказа JSON | `%paver_order_json%` |
| Итоговая сумма | `%paver_total%` |
| Сумма скидки | `%paver_discount%` |
| Количество поддонов | `%paver_pallets%` |
| Общий вес | `%paver_weight%` |
| Версия прайса | `%paver_price_version%` |
| Страница расчёта | `%paver_page_url%` |
| Источник заявки | `%paver_source%` |
| Логистика | `%paver_logistics%` |

Если Bitrix24 не разрешает параметр `%...%` в числовом поле, пересоздайте поля «Итоговая сумма», «Сумма скидки», «Количество поддонов» и «Общий вес» как тип **Строка**. Это технические поля передачи; числа будут приходить строками без потери данных.

## Подключение

1. Загрузите содержимое архива в корень GitHub-репозитория.
2. На странице Аспро вставьте содержимое `bitrix-aspro-snippet.html`.
3. Старый виджет Bitrix24 в правом углу не удаляйте.
4. Очистите jsDelivr для нового адаптера:
   `https://purge.jsdelivr.net/gh/miropolcevpro/prev_img_ag_2_026@main/paver-bitrix24-adapter.js`
5. Очистите композитный и управляемый кэш Bitrix.

## Что делает адаптер

- использует единое ядро и единый прайс из GitHub;
- на Tilda ничего не меняет;
- на сайте Bitrix меняет ссылку политики на `https://st-ru.com/policy/_1.0.6_index.php`;
- скрывает встроенную Tilda-форму калькулятора;
- добавляет кнопку «Отправить расчёт»;
- открывает ту же CRM-форму Bitrix24 ID 10 в модальном окне;
- передаёт состав заказа, JSON, сумму, скидку, поддоны, вес, версию прайса, URL и источник;
- логистика передаётся как «Отключена».

## Проверка

В консоли страницы:

```js
window.PaverBitrix24Adapter.diagnose()
```

Ожидается:

- `version: "paver-bitrix24-adapter-20260615-1"`
- `root: true`
- `formId: 10`
- после открытия формы `initializedForms >= 1`
- в `payload.positionsCount` количество позиций корзины.

После тестовой отправки откройте созданный лид и проверьте все скрытые поля.
